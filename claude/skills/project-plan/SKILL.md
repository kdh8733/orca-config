# /project-plan - 마일스톤 분해와 ROADMAP.md

목적: Goal을 작은 단위(반나절~수일)의 **검증 가능한** 마일스톤으로 분해한다.
고도 규칙: 여기서는 "무엇을 어떤 순서로, 완료를 어떻게 확인하나"까지만.
파일 단위 구현 설계는 superpowers `writing-plans`로 핸드오프한다(중복 작성 금지).

## 진행 순서

1. **현재 상태 파악**: `~/.claude/knowledge/<domain>/ontology.yaml` 과 기존
   ROADMAP.md/README를 읽는다. Goal이 없으면 /project-init 부터 권한다.
2. **분해**: 글로벌 CLAUDE.md "목표 기반 실행" 포맷을 따른다 -
   각 단계는 `[단계] → 검증: [체크]` 형태여야 하며, 검증이 안 떠오르는
   단계는 너무 크다는 신호이므로 더 쪼갠다.
3. **순서/의존성**: 의존 관계와 차단 요소(외부 대기, 미확정 결정)를 표시.
   추측성 단계(요청 안 된 기능, 미래 대비 추상화)는 "후순위/보류" 섹션으로 격리.
4. **ROADMAP.md 작성/갱신** (프로젝트 루트, 아래 골격):

```markdown
# 로드맵 - <프로젝트>
> Goal: <한 줄> / 완료 기준: <검증 가능한 기준> / 갱신: YYYY-MM-DD

## 마일스톤
- [ ] M1 <단계> - 검증: <체크 명령/관찰>
- [ ] M2 <단계> - 검증: <체크>   (의존: M1)

## 후순위 / 보류
- <항목> - 보류 사유

## 완료 기록
- [x] M0 <단계> (YYYY-MM-DD) - 검증 결과 한 줄
```

5. **마무리**: 완료된 마일스톤은 지우지 않고 "완료 기록"으로 이동(회고 자산).
   ROADMAP이 ontology에 앵커로 등록돼 있는지 확인하고 없으면 추가한다.
